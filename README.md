# RUSSIA'S CRIMES — Against Journalists & Media

**Злочини Росії проти журналістів і медіа в Україні** — інтерактивна платформа моніторингу Інституту масової інформації (ІМІ).

Публічна двомовна сторінка (UA `/`, EN `/en`), закрита адмін-панель для одного редактора, генератор PNG-інфографіки (1080 × 1350, 1920 × 1080, Open Graph) та журнал версій статистики.

**Сайт:** https://sf2224.github.io/rsm/ — статична версія публічної частини, яка автоматично збирається з `data/published/snapshots.json` при кожному push у `main` (див. [«GitHub Pages»](#github-pages)).

Усе, що бачить відвідувач, береться з одного опублікованого знімка даних: сторінка, англійська версія, картки категорій, PNG-експорт і превʼю в соцмережах. Чернетки на сайт не потрапляють.

| Шар | Рішення | Чому |

## Швидкий старт (локально)

Потрібно: Node.js ≥ 22.12 (рекомендовано 22 LTS), npm.

```bash
npm ci
cp .env.example .env          # перевірте значення
npm run db:migrate            # створює var/imi.db
npm run db:seed               # стартові дані ІМІ (див. нижче)
npm run admin:create          # створює адміністратора, пароль вводиться приховано
npm run dev                   # http://localhost:3000
```

Адмін-панель: `http://localhost:3000/admin` (посилання на неї в публічному інтерфейсі немає).

**Що робить `db:seed`.** Завантажує знімок станом на 24.10.2026 у статусі «На перевірці», а також історичний знімок станом на 24.09.2026 як чернетку для звірки. Нічого не публікується автоматично: сума категорій (990) не дорівнює головному показнику (989), і цю розбіжність має підтвердити й пояснити редактор. Поки публікації немає, сайт показує «Дані готуються до публікації».

Щоб побачити публічну сторінку без проходження перевірки, на **локальній** базі можна виконати `npm run db:seed -- --local-preview`: знімок буде опубліковано з позначкою «[ЛОКАЛЬНИЙ ПЕРЕГЛЯД]». У продакшні цей прапорець вимкнено.

## Щомісячне оновлення даних

1. `/admin` → **«Новий щомісячний знімок (копія поточного)»**. Створюється чернетка з даними поточної публікації; підтвердження скидаються.
2. **Основне**: головний показник, дата «станом на», звітний період, нові випадки, загиблі медійники, посилання на публікації ІМІ.
3. **Категорії**: числа, назви UA/EN, необовʼязкові пояснення, порядок, приховування. Ідентифікатор категорії постійний, він використовується в посиланнях `/#category-threats`.
4. **Динаміка**: точки з опублікованими раніше загальними показниками ІМІ (дата, усього, загиблі, джерело, примітка) і короткі підсумки років. Поточний знімок додається до графіка сам.
5. **Тексти UA/EN**: назва періоду (кнопка «Підставити» розраховує «4 роки і 8 місяців…» з дат), публічна примітка.
6. **Зберегти чернетку** → **Передати на перевірку**.
7. **Перевірка**: звірка суми категорій із головним показником, підтвердження звірки з першоджерелом, пояснення розбіжності (UA+EN), список попереджень порівняно з попереднім знімком.
8. **Попередній перегляд**: сторінка UA/EN і всі PNG саме з цими даними.
9. **Опублікувати** (для підтвердження вводиться дата знімка). Сайт одразу показує нові дані, а сервер записує JSON-копію.

Виправлення вже опублікованого: «Створити виправлену версію» → та сама послідовність. Стара версія зберігається зі статусом «Замінено» і може бути **відновлена** одним кліком. «Зняти з публікації» прибирає помилкову або зловмисну публікацію; сайт повертається до попереднього знімка.

## Модель даних

Таблиця `snapshot` — версії статистики. Кожна версія зберігає повний документ `SnapshotData` у JSON разом із SHA-256 контрольною сумою:

- `totalCrimes` — головний показник ІМІ (вводиться, **ніколи** не розраховується з категорій);
- `asOfDate`, `monitoringStart`;
- `period` — останній звітний місяць і кількість нових випадків;
- `casualties` — загиблі медійники всього / під час роботи (окремі величини, з головним показником не додаються);
- `categories[]` — `id`, `iconId`, `value`, `order`, `hidden`, `name{uk,en}`, `description{uk,en}`;
- `texts` — назва періоду, публічна примітка (UA/EN);
- `history.points[]` — опубліковані раніше загальні показники ІМІ (`date`, `total`, `killedTotal`, `killedOnDuty`, `note{uk,en}`, `source`); кожна точка має посилання на першоджерело;
- `history.years[]` — підсумок календарного року (`year`, `killedInYear`, `note{uk,en}`, `source`);
- `sources` — посилання на публікації ІМІ та реєстр;
- `verification` — підтвердження редактора і пояснення розбіжності.

Статуси: `draft` → `review` → `published`; далі `superseded` (замінено виправленням) або `withdrawn` (знято). На рівні бази є унікальний індекс: не більше однієї опублікованої версії на період. На сайті «поточний» знімок — опублікований з найпізнішою датою; решта формує історію.

Показник ІМІ накопичувальний. Блок «Як змінювалися цифри» будує графік з `history.points` і поточного знімка, а картки років показують значення на кінець року та зміну показника за рік (різниця між кінцевими значеннями сусідніх років, а не «кількість злочинів за рік»). У листопаді 2024 ІМІ додав до показника 329 закритих медіа, це позначено приміткою на графіку. Майбутні роки не показуються, порожні роки не заповнюються нулями. Усі 51 точку 2022–2026 внесено лише з публікацій на imi.org.ua (щомісячні релізи моніторингу та річні підсумки ІМІ); посилання є в даних і в таблиці під графіком. Валідація не дозволяє зберегти точку без посилання.

Інші таблиці: `admin_user`, `session` (зберігається лише хеш токена), `login_throttle`, `audit_log`.

## PNG-експорт

- `GET /api/export/social?lang=uk&slide=1` — 1080 × 1350. Слайд 1: заголовок на всю ширину, шкала тривалості війни (позначка на кожен місяць), блок із загальним показником і три блоки: нові випадки, загиблі, загиблі під час роботи. Далі по 14 категорій на слайд блоками у дві колонки (іконка, число, назва), примітка і джерело. Кількість слайдів рахується автоматично (`src/lib/export/plan.ts`).
- `GET /api/export/wide?lang=en&slide=1` — 1920 × 1080: ліворуч заголовок, шкала війни, загальний показник і блоки з загиблими; праворуч 14 категорій блоками у три колонки та блок із приміткою.
- `GET /api/export/zip?lang=uk&set=social|all` — ZIP зі слайдами.
- `GET /api/og?lang=uk` — 1200 × 630 для превʼю посилань.

Посилання на джерело на сайті: під текстом першого екрана, перед кнопкою «Режим презентації», рядок «Цитуючи дані, зазначайте джерело: Інститут масової інформації»; у центрі діаграми на головній і в режимі презентації підпис «за даними ІМІ, станом на …»; під час копіювання тексту зі сторінки до буфера обміну додається рядок «Джерело: Інститут масової інформації (ІМІ), <адреса сайту>» і з'являється коротке повідомлення про це (`src/components/site/CopyCredit.tsx`).

Правила інфографіки:

- Логотип ІМІ однакового розміру й на тому самому місці на всіх слайдах одного формату, щоб у каруселі в соцмережах він не «стрибав»: 1080 × 1350 — 64 px заввишки, по центру, 72 px від верхнього краю; 1920 × 1080 — 58 px у лівому верхньому куті. Розміри задано одним місцем, `LOGO_HEIGHT` у `src/lib/export/templates.tsx`.

Розмір цифр підлаштовується під кількість розрядів, тож показник 1 000, 2 000 і більше вміщується на всіх форматах (перевірено на 2 140). На кожному зображенні є офіційний логотип ІМІ потрібною мовою та дата актуальності. Шрифти читаються з `assets/fonts` (жодних мережевих запитів), текст перетворюється на криві, тож результат не залежить від системних шрифтів сервера. Результати кешуються за контрольною сумою знімка; для публічних маршрутів діє обмеження частоти запитів і одночасних рендерів.

## Резервні копії та відновлення

- Після кожної публікації, зняття чи відновлення сервер автоматично пише JSON-копію в `BACKUP_DIR` (зберігаються останні 500 файлів).
- `/admin/backups`: завантажити JSON; імпортувати JSON **як чернетки** (з інтерфейсу нічого не публікується); перевірити цілісність.
- `npm run db:restore -- backups/….json`: повне відновлення стану сайту зі статусами (перед цим записується страхувальна копія поточного стану).
- Контрольні суми перевіряються під час читання: пошкоджену публікацію сайт не покаже, а адмінка про неї попередить.

## Тести та перевірки

```bash
npm run typecheck && npm test && npm run build
```

Тести (`tests/`) охоплюють:

- валідацію: розбіжність суми, переклади, дати, XSS у текстах, лише https;
- робочий процес публікації: незмінність опублікованого, атомарне збереження, захист від застарілих збережень, виправлення, відкат, зняття;
- цілісність і резервні копії;
- авторизацію API: 401 без сесії, 403 без CSRF або з чужого Origin, 415 для не-JSON, блокування після 5 невдалих входів, параметри cookie;
- PNG: точні розміри, обидві мови, розбиття на слайди, ZIP.

Окремо перевірено роботу на PostgreSQL 16 з роллю застосунку без прав `DROP`/`DELETE` на журнал аудиту (див. `docs/DEPLOYMENT.md`).

## GitHub Pages

Публічна частина працює і як статичний сайт. Workflow `.github/workflows/pages.yml` на кожен push у `main`:

1. запускає тести;
2. перевіряє `data/published/snapshots.json` за правилами публікації (знімки без підтвердження редактора на сайт не потрапляють, причина видна в журналі Actions);
3. заздалегідь рендерить усі PNG і ZIP;
4. збирає HTML (`npm run build:static`) і викладає його в гілку `gh-pages`.

Одноразове налаштування: **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `gh-pages` / `(root)` → Save.**

Серверна адмін-панель і API у статичну версію не входять: їм потрібен сервер. Для Pages є **редактор даних** за адресою `/editor/` (https://rucrimes.imi.org.ua/editor/):

- редагує `data/published/snapshots.json` у репозиторії: головний показник, дати, загиблих, категорії, точки динаміки та підсумки років (цифри, примітки, посилання), тексти UA/EN, першоджерела;
- два сценарії на першому екрані: «Виправити поточні дані» (уточнення в будь-який день) і «Додати нові дані» на обрану дату (попередні цифри автоматично стають точкою на графіку);
- кнопка «Перевірити й опублікувати» відкриває вікно перевірки: що зміниться на сайті, помилки з переходом до потрібного розділу, попередження (не блокують публікацію) і підтвердження редактора. Якщо сума видів порушень відрізняється від головного показника, редактор підтверджує це там само й залишає пояснення для сайту;
- будь-яка зміна цифр чи текстів знімає попередні підтвердження, тож їх дають саме для того, що публікується;
- публікація = один коміт у `main`; далі Actions перебудовує сайт і всі PNG (близько 2 хвилин). Журнал змін — історія комітів файлу, відкат — `git revert` або повторна публікація старих значень;
- заплановані публікації: дату «станом на» можна поставити до 14 днів уперед (і в новому оновленні, і у виправленні поточних даних). Такий запис зберігається у файлі, але збірка його пропускає, поки дата не настала; поточні цифри лишаються на сайті. Щодня о 00:07 за Києвом (влітку о 01:07) workflow перевіряє, чи є запис на сьогодні або вчора, і якщо так, перебудовує сайт. У редакторі заплановані записи видно окремим блоком, їх можна змінити або скасувати;
- вхід: fine-grained токен GitHub з доступом лише до `sf2224/rsm` (Contents: Read and write; Actions: Read — щоб бачити статус публікації). Токен зберігається тільки в браузері, зашифрований паролем редактора (PBKDF2-SHA-256, 600 000 ітерацій, AES-GCM). На сервер ІМІ чи будь-куди, крім api.github.com, він не передається;
- внутрішні нотатки в репозиторій не записуються: репозиторій публічний.

Файл також можна змінювати прямо в GitHub або вивантаженням з локальної адмінки (`npm run pages:export`). Подробиці — у [data/published/README.md](data/published/README.md).

Домен: сайт працює на https://rucrimes.imi.org.ua/ (DNS: CNAME `rucrimes` → `sf2224.github.io`; домен підтверджено в акаунті sf2224 через TXT `_github-pages-challenge-sf2224.rucrimes`, цей запис не видаляти). Workflow за замовчуванням збирає сайт для цього домену й кладе файл `CNAME` у gh-pages. Змінна репозиторію `PAGES_DOMAIN` замінює домен; значення `off` повертає адресу `https://sf2224.github.io/rsm/`. Якщо сайт колись закриють, одразу видаліть CNAME-запис у DNS.

## Сервер і продакшн

- Секрети та бази даних не потрапляють у Git (`.gitignore`): `.env`, `*.db`, `var/`, `backups/`.
- CI (`.github/workflows/ci.yml`): typecheck, тести, `npm audit`, збірка. Dependabot стежить за залежностями.
- Повна версія з адмінкою онлайн потребує Node.js-хостингу (VPS, Docker або PaaS) і PostgreSQL. Покрокова інструкція — у [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Що потрібно додати

- **Англійський SVG-логотип.** Окремого файлу не надано; `public/brand/imi-logo-en.svg` зібрано з векторних кривих англійської інфографіки ІМІ (знак і напис «INSTITUTE OF MASS INFORMATION»). Якщо є офіційний файл, замініть цей.
- **Інші накреслення Kyiv Type Sans.** Надано лише Bold, тож він використовується для заголовків і цифр. Ліцензія шрифту забороняє похідні файли, тому його не конвертовано у WOFF2.
- **Пояснення розбіжності 990 ≠ 989.** Його має надати редакція ІМІ (див. `docs/DATA_AUDIT.md`).
- **Історичні знімки.** Повні знімки з категоріями внесено лише за жовтень 2026 (і вересень як чернетку для звірки). Динаміку загального показника 2022–2026 внесено окремо (`history`), її можна доповнювати у вкладці «Динаміка».
- **Пояснення до категорій** (необовʼязкові) не заповнені: формулювання методології має дати ІМІ.
